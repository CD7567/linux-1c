# Задание

В изначальной постановке сформулировано так: системный вызов для преобразования VA в PA.

Попробуем написать для себя ТЗ, чтобы аггрегировать нужную информацию и сбить планируемую архитектуру.

## Предлагаемая архитектура

### Назначение
Предоставить привилегированному процессу (root) возможность получить информацию о сопоставлении одного виртуального адреса из пользовательского адресного пространства текущего процесса с физической страницей (PFN/PA) или состоянием страницы (present/swapped/unmapped).

### Интерфейс
Структура данных запроса/ответа в пользовательском пространстве:
```c
struct vapa_req {
    __u64 va;        // [in]  виртуальный адрес в адресном пространстве текущего процесса
    __u64 pa;        // [out] физический адрес (если статус PRESENT и страница в RAM)
    __u64 pfn;       // [out] номер физического кадра (page frame number), если доступен
    __u64 flags;     // [out] битовые флаги, описывающие состояние/тип страницы
    __s32 status;    // [out] код результата (см. ниже)
};
```

Сигнатура syscall:
```c
long sys_va_to_pa(struct vapa_req __user *req);
```

### Семантика и поведение
1. Область действия:
    - Syscall работает **только с адресами пользовательского пространства** текущего процесса.
    - Попытка передать kernel‑адрес или адрес вне пользовательского диапазона приводит к статусу `VAPA_STATUS_NOACCESS` или ошибке `-EFAULT` (на усмотрение реализации).

2. Права доступа:
    - Вызов разрешён только процессу с эффективным UID 0 (root) или с соответствующей привилегией (например, `CAP_SYS_ADMIN`).
    - Для непривилегированных процессов syscall возвращает ошибку `-EPERM`.

3. Входные данные:
    - Поле `va` задаёт любой виртуальный адрес в пользовательском адресном пространстве текущего процесса; выравнивание на границу страницы не требуется.
    - Остальные поля структуры на входе могут быть произвольными и игнорируются.

4. Выходные данные:
    - `status`:
      - `VAPA_STATUS_PRESENT` — страница отображена и присутствует в RAM.
      - `VAPA_STATUS_SWAPPED` — страница отображена, но выгружена в swap.
      - `VAPA_STATUS_UNMAPPED` — по данному адресу нет отображения (нет VMA/PTE).
      - `VAPA_STATUS_NOACCESS` — адрес вне допустимого диапазона пользовательского пространства или иная нарушение политики доступа.
      - `VAPA_STATUS_ERROR` — внутренняя ошибка (неудача обхода таблиц страниц и т.п.).
    - `pfn`:
      - Валиден только при `status` == `VAPA_STATUS_PRESENT`.
    - `pa`:
      - При `status` == `VAPA_STATUS_PRESENT` содержит физический адрес.
      - При других статусах значение не определено (может быть обнулено).
    - `flags` (битовое поле, комбинируется по `OR`):
      - `VAPA_FLAG_PRESENT` — страница присутствует в RAM.
      - `VAPA_FLAG_SWAPPED` — страница находится в swap.
      - `VAPA_FLAG_ANON` — анонимная страница (heap/stack и т.п.).
      - `VAPA_FLAG_FILE` — страница отображает файловый mapping.
      - `VAPA_FLAG_HUGE` — страница принадлежит huge page/THP.
      - `VAPA_FLAG_SOFT_DIRTY` — страница помечена как soft-dirty (если ядро поддерживает этот бит).

5. Ошибки возврата syscall (общий long):
    - `0` — успешное выполнение, поля структуры содержат результат (status, flags, pfn, pa и т.д.).
    - `-EPERM` — недостаточно прав.
    - `-EFAULT` — указатель req указывает на недоступную область памяти в user space.
    - `-EINVAL` — некорректные аргументы

6. Гарантии и ограничения:
    - Syscall только читает состояние таблиц страниц и не инициирует page fault, не аллоцирует новые страницы и не изменяет состояние памяти процесса.
    - При обращении к лениво выделенной странице (lazy allocation) разрешено возвращать `UNMAPPED` без попытки материализовать страницу.
    - Интерфейс рассчитан на запрос одного адреса за один вызов.
