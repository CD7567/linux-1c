# Домашнее задание

## Файловый интерфейс к мессенджеру

**Курс:** Системная разработка и ядро Linux  
**Тема:** Модули ядра и файловые интерфейсы

## 1. Цель задания

Цель задания — познакомиться с:

- разработкой модулей ядра Linux;
- реализацией файловых интерфейсов;
- взаимодействием kernel space ↔ user space;
- использованием системных вызовов `read` / `write` / `open` / `close`;
- проектированием API поверх файловой модели Unix.

## 2. Идея задания

Необходимо реализовать систему, которая предоставляет файловый интерфейс к чатам мессенджера.

Каждый чат представлен как файл.

Файловые операции интерпретируются следующим образом:

| Операция | Значение |
|---|---|
| `open()` | открыть чат |
| `read()` | получить последние сообщения |
| `write()` | отправить сообщение |
| `close()` | закрыть чат |

Таким образом, взаимодействие с мессенджером выглядит как обычная работа с файлами Linux.

## 3. Пример использования

После загрузки модуля пользователь должен иметь возможность работать с чатами следующим образом:

```bash
cat /dev/telegram/chat_1
```

Вывод:

```text
[Мария] Привет
[Владимир] Добрый день
[Мария] Как дела?
```

Отправка сообщения:

```bash
echo "Всем привет" > /dev/telegram/chat_1
```

Повторное чтение:

```bash
cat /dev/telegram/chat_1
```

```text
[Мария] Привет
[Владимир] Добрый день
[Мария] Как дела?
[Мария] Готов к пересдаче?
```

## 4. Архитектура системы

Система должна состоять из двух компонентов.

### 4.1 Модуль ядра Linux

Модуль ядра должен:

- создать файловый интерфейс для чатов;
- реализовать файловые операции;
- передавать запросы в пользовательское пространство.

Минимально должны быть реализованы функции:

- `open`
- `read`
- `write`
- `release`

Модуль может использовать один из следующих механизмов:

- `procfs`
- `debugfs`
- `character device`

### 4.2 Пользовательская программа

Пользовательская программа должна играть роль API к мессенджеру или эмулятора мессенджера.

Она должна:

- хранить чаты;
- хранить сообщения;
- возвращать историю сообщений;
- принимать новые сообщения.

Программа может хранить данные:

- в памяти;
- в простых структурах данных.

Подключение к реальному Telegram не требуется.

## 5. Функциональные требования

Система должна поддерживать следующие возможности.

### 5.1 Чаты

Необходимо реализовать доступ к списку чатов (не менее 3 чатов в случае варианта с эмулятором).

Например:

```text
/dev/telegram/chat_1
/dev/telegram/chat_2
/dev/telegram/chat_3
```

### 5.2 Чтение сообщений

Операция `read()` должна возвращать:

- последние сообщения чата;
- минимум 10 сообщений либо все, если их меньше.

Формат сообщений может быть текстовым, например:

```text
[user] message
```

### 5.3 Отправка сообщений

Операция `write()` должна добавлять новое сообщение в чат.

Пример:

```bash
echo "Hello" > /dev/telegram/chat_1
```

Это должно привести к появлению нового сообщения в истории.

### 5.4 Независимость чатов

Сообщения разных чатов не должны смешиваться.

Запись в один чат не должна влиять на другие.

### 5.5 Обработка ошибок

Необходимо корректно обрабатывать ошибки:

- обращение к несуществующему чату;
- слишком длинное сообщение;
- ошибки копирования между user space и kernel space;
- ошибки протокола взаимодействия.

## 6. Ограничения

В рамках задания не требуется:

- подключение к реальному Telegram API;
- реализация сетевого протокола;
- хранение сообщений на диске;
- полноценная многопользовательская система.

Допускается хранение всех данных в оперативной памяти.

## 7. Дополнительные задания (по желанию)

```text

```

- Метка времени сообщений. Формат:

```text

```

  - получить количество сообщений;

  - Файл должен становиться читаемым при появлении новых сообщений.
- Кольцевой буфер.
  - Хранить только последние `N` сообщений.
- Поддержка нескольких клиентов.
  - Корректная синхронизация доступа: `mutex`, `spinlock`.

## 9. Проверка работы

Для защиты необходимо продемонстрировать:

1. сборку модуля;
2. загрузку модуля (`insmod`);
3. запуск пользовательской программы;
4. чтение сообщений;
5. отправку сообщений.

Пример:

```bash
sudo insmod telegram_fs.ko
./telegram_server
cat /dev/telegram/chat_1
echo "Hello world" > /dev/telegram/chat_1
cat /dev/telegram/chat_1
```

- правильная реализация `read` / `write` / `open` / `release`;
- корректная работа `kernel <> user space`;
- обработка ошибок.
